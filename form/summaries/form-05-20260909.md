## Round 1 - Simple

**Prompt:** A user reports a bug in something you built. Walk me through what actually happens to that bug report from the moment it lands to the moment you close it - how you confirm it's real, how you find the cause, and how you decide it's fixed.

**中文：**讲讲一个用户报的 bug 在你手里的完整流程——从收到、确认是真问题、定位原因，到你判断它修好了可以关掉。

**He wrote:**
> Whenever I receive a bug, I'll check how it triggers to confirm whether it's from frontend or backend and whether it's really a problem. If it's a frontend bug, I'll try to reproduce it on my computer and locate the code snippet. If it's a backend bug, I'll check the logs and analyze the exception stacks to locate where the problem is. After I correct the code and test it properly, I'll ship it.

**tense:** ok

**article:** "whether it's from frontend or backend" -> "from the frontend or the backend" (bare singular countables, `chat:E031`)

**form:** ok

**object:** "I'll check how it triggers" -> "how it's triggered" (the bug does not trigger anything, it gets triggered; `trigger` left without its object, `chat:E055`)

**Note:** Not counted, and the most interesting thing in the drill. He wrote **"test it properly"** - the exact target form of `chat:E027` (*I have to test carefully* -> *test it properly*), produced unprompted, object present. A drill cannot resolve a row, but the phrase has now appeared on its own. Nine verbs in the round were all correctly shaped, which is why `form` is clean. Out of scope: "whenever I receive a bug" - what arrives is a bug *report*; the bug was already in the code.

## Round 2 - Medium

**Prompt:** Take one specific piece of code you inherited from someone else and had to work on - a class, a service, a config file, whatever. Tell me everything you did to it, in order: what state it was in when you got it, what you changed, what you left alone and why, and what you'd still do to it if you had the time.

**中文：**挑一段你从别人手里接过来、必须动的代码。按顺序讲你对它做的所有事：接手时它是什么状态、你改了什么、什么没动以及为什么、如果有时间你还想对它做什么。

**He wrote:**
> Last year I took over a requirement from my colleague who would quite job a month later. The requirement was about a ticket review function, and he had designed the table scheme and just built abstract service. When I inherited the codebase from him, I'd got to continue his development. First of all, I looked into the core logic and implemented the CheckService. Since his table scheme could meet the needs, I just had to build the review function. Based on his design, I'd got to insert the ticket data and init its status whenever a review request had been received. I'd got it done and shipped it after two weeks. If I had more time, I would optimize my code structure by using an abstract template pattern.

**tense:** "whenever a review request had been received" -> "whenever a review request came in" (past perfect inside a general rule about system behaviour); plus "I'd got to continue" / "I'd got to insert" -> "I had to" (`have got to` is present-only and has no past form)

**article:** "just built abstract service" -> "built an abstract service" (bare singular countable, `chat:E031`)

**form:** ok

**object:** ok

**Note:** Not counted. The `object` result is the point of the round, so it is worth naming the verbs: `designed the table scheme`, `built abstract service`, `implemented the CheckService`, `build the review function`, `insert the ticket data`, `init its status`, `got it done`, `shipped it`, `optimize my code structure`. Nine transitive verbs on one named thing, first pass, no drops - against a prompt shaped to reproduce Day 05. The counterfactual "If I had more time, I would optimize" is also built correctly on both halves. Out of scope: "would quite job" needs `quit his job`; "table scheme" is `schema`, twice; "shipped it after two weeks" needs `in`; "init its status" is written jargon for `set`; "took over a requirement" is a calque for "took over a feature".

## Round 3 - Hard

**Prompt:** A new engineer joins and needs to know what your production environment physically consists of before they can be on call. Inventory it for them: the servers and how many, the databases, the load balancer, the caches, any message queues, and the monitoring. Say what exists, roughly how many of each, and which pieces talk to which.

**中文：**新同事要值班，得先知道你们生产环境有哪些东西。给他盘点一遍：几台服务器、什么数据库、负载均衡、缓存、消息队列、监控各是什么，大致数量多少，谁跟谁通信。

**He wrote:**
> So let me introduce the production components for you. We have a Kubernetes cluster which contains eight Linux server nodes. Our database is Mysql and its version is 5.7.1. The load balancer is Aliyun balancer. The cache is Redis and we are using RabbitMQ. We can monitor all services on the dashboard whose url is "/dashboard/analysis/". And notice that we just deploy our business services on the Kubernetes cluster. Other middlewares are deployed on VM servers. The user service is using Redis to save user token, and whenever a use login request comes in, the operation will be logged by RabbitMQ.

**tense:** ok

**article:** "to save user token" -> "to save the user's token" / "to save user tokens" (bare singular countable, `chat:E031`)

**form:** ok

**object:** ok

**Note:** Not counted. Eight verb shapes correct including two passives (`are deployed`, `will be logged`), which is what a noun-dense inventory round is least likely to produce cleanly. Out of scope: "middlewares" is uncountable, so "other middleware is deployed"; `MySQL` and `Aliyun Load Balancer` are capitalisation; "introduce ... for you" needs `to you`; "a use login request" is a typo for `user`. Content-wise "The cache is Redis and we are using RabbitMQ" packs two unrelated components into one clause and never says what the queue is for.

## What It Showed

**1. `object` survived the round built to break it.**

Round 2 was written to the Day 05 shape - many actions on one already-named thing -
because that shape produced three `chat:E055` misses in a single session. It came
back with nine transitive verbs and no drops, on a first pass with no hand-back.
Round 3 was clean too. The one miss was Round 1, and it is a different mechanism from
the row: not an object omitted from a transitive verb, but a transitive verb used
where the passive was needed (*how it triggers* for *how it's triggered*), which is
the same shape as *to see what it changes* in Drill 03 - also Round 1.

Set against Day 12 taking `chat:E055` to 8 hits in real conversation, the reading is
that the row is alive in unmarked speech and suppressible in a drill. That gap is the
finding, not the clean columns.

**2. `article` has now missed in six consecutive rounds.**

Every round of Drill 04 and every round of Drill 05. All six were the same mechanism,
`chat:E031`, bare singular countable: *Readme*, *the pages*, *has right to*,
*frontend or backend*, *abstract service*, *user token*. Control 01 scored 12/12 on
this material on 2026-09-04.

Five drills, one control, and an error row at 10 hits that has not moved. Marking it
in arrears demonstrably does not work, and this is now the strongest result the track
has produced - a negative one about its own method.

**3. `form` was clean in all three rounds for the first time.**

Twenty-plus verbs across the drill, including two passives, a correctly built
counterfactual (*If I had more time, I would optimize*), and a correlative that had
failed in Drill 04. `form` was the axis that justified adding a fourth column at all;
it has now gone from three misses in Drill 04 to zero.

The `have got to` errors are worth separating from this. They landed in `tense`
because the fault is a missing past form, not a wrong verb shape - but three
instances in one round of an idiom that has no past tense suggests a fixed-phrase
problem rather than a grammar one.

**4. The self-correction was near-total but not self-directed.**

He revised Round 2 unprompted and asked for a check. Both marked misses were fixed,
and so were three of the five out-of-scope notes. What survived: `quite` for `quit`,
`scheme` for `schema` (twice), and a third `I'd got it done` - after he had corrected
the same idiom twice in the same paragraph.

So the split is clean. Errors that were **named** got fixed at close to 100%. Errors
he would have had to **find** got fixed at zero, including a repeat of a pattern he
had just corrected. This is the same attention result the whole track keeps producing,
now visible inside a revision rather than a first draft - and it is direct evidence
on Drill 04's Carry Forward item 2, which proposed self-checking as the next
instrument. A self-check appears to correct what is already flagged rather than find
what is not.

   chat is not. Stop building rounds for it and let the daily chat carry the row.
3. **Consider a `fixed-phrase` note for `have got to`.** Three instances in one round,
   all past-tense uses of a present-only idiom. Currently absorbed into `tense`,
   which hides it. Not a new axis - a note to watch whether it recurs.
4. **The passive-for-transitive shape now has two instances.** *what it changes*
   (Drill 03 R1), *how it triggers* (Drill 05 R1), both in Round 1. It is filed under
   `object` but is not `chat:E055`'s mechanism. Third instance splits it.
5. **`chat:E056` did not recur.** Opened at 3 hits after Drill 04, no wrong-definiteness
